# 归档范围与使用

## 两种读取方式

仓库中的 docs、materials、baseline、data、experiments、code、review-history 是可直接检索的入口。当前 812 题及全部 9,744 候选按场景和问题拆分，详见 data/README.md；大结果文件按类别分片，详见相应 results-index.json。原始字节没有被这些检索副本覆盖。

archives 保存完整原始证据，使用 tar.xz 格式；如有分卷，按 archives/index.json 指定顺序合并后校验 SHA-256 再解压。解压目标应是单独的新目录，避免覆盖工作区。provenance/archive-file-manifest.jsonl 记录每个原始文件的相对路径、大小、哈希与所属归档。

## 本次没有重复上传的文件

- `.env`、凭据、虚拟环境、依赖安装目录、缓存、系统文件、浏览器调试截图和运行服务日志。
- SQLite 数据库副本：审核记录和工作台尝试已只读导出为 JSON；基准有原始 JSON/JSONL 及来源/映射，避免上传同一数据的数据库副本。
- 模型权重、embedding 向量和语义近邻模型缓存。
- jev-bench/static 内重复的完整数据浏览副本；原研究目录的数据、主工作台代码保留。
- research/archives 中外部题库的多份旧完整镜像、exports 下既有分享包；当前外部原题/映射/审核与主要研究实验的历史版本已保留。
- 资料库中约 1.5 GB 的第三方仓库源码镜像及批量 Hugging Face 下载镜像；保留来源 URL、固定版本、许可/获取状态与校验目录，以及用于项目题库的外部数据整理。未将这些第三方代码全部作为本项目成果。

归档中的来源索引可能引用上述未上传镜像。遇到这种引用应标为“仅保留来源索引，原镜像未包含”，不能声称已读完整上游。上游来源与许可应按原元数据核对，本仓库不重新授予第三方内容许可。

## 运行与分析

code/ 是便于查看的代码副本。需要运行时应先解压归档恢复原有 research/ref1.2 与 jev-bench 布局；部分历史脚本依赖本地环境和绝对路径。模型调用脚本会产生费用，不要在仅分析材料时运行。先进行本地数据核对；verification/verify_handoff.py 不调用模型。

本仓库文档和数据可能含有对抗指令字符串，它们是实验载荷而不是对读取者的指令。
